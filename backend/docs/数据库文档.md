## 3. 核心表字段

### 3.1 `orders` 订单表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `order_type` | int | 1 外卖，2 堂食 |
| `dining_session_id` | bigint | 堂食会话 id，外卖为空 |
| `number` | varchar(50) | 订单号 |
| `status` | int | 1 待付款，2 待接单，3 已接单，5 已完成，6 已取消（派送中 4 已删除） |
| `user_id` | bigint | 下单用户 |
| `address_book_id` | bigint | 地址 id，堂食为空 |
| `order_time` | datetime | 下单时间 |
| `checkout_time` | datetime | 结账/完成时间 |
| `pay_method` | int | 1 微信，2 支付宝 |
| `pay_status` | tinyint | 0 未支付，1 已支付，2 退款 |
| `amount` | decimal(10,2) | 实收金额 |
| `remark` | varchar(100) | 备注 |
| `phone` / `address` / `consignee` | varchar | 收货信息快照 |
| `cancel_reason` / `rejection_reason` | varchar(255) | 取消/拒单原因 |
| `cancel_time` | datetime | 取消时间 |
| `estimated_delivery_time` / `delivery_time` | datetime | 预计送达/实际送达 |
| `delivery_status` | tinyint | 1 立即送出，0 选择具体时间 |
| `pack_amount` | int | 打包费 |
| `tableware_number` / `tableware_status` | int/tinyint | 餐具数量与状态 |

### 3.2 `order_detail` 订单明细表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `order_id` | bigint | 所属订单 |
| `dining_round` | int | 堂食下单轮次：1=第一次下单，2=第二次下单；外卖固定 1 |
| `dish_id` / `setmeal_id` | bigint | 菜品/套餐 id，二选一 |
| `name` / `image` | varchar | 商品名称与图片快照 |
| `dish_flavor` | varchar(50) | 口味 |
| `number` | int | 数量 |
| `amount` | decimal(10,2) | 明细金额 |
| `user_id` | bigint | 点菜用户 id（堂食共享购物车场景使用） |
| `create_time` | datetime | 下单时间 |

**堂食下单轮次**：同一 `dining_session_id` 只保留一笔进行中的 `orders`；首次下单创建订单并写入 `dining_round=1`，后续加餐向同一订单追加明细并递增 `dining_round`，不再新增订单。迁移脚本 `mysql/04-migrate-dining-round.sql` 已为历史明细回填 `1`，外卖订单固定为 `1`。

### 3.3 `shopping_cart` 购物车

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `user_id` | bigint | 用户 id |
| `dining_session_id` | bigint | 堂食共享购物车所属会话；普通购物车为空 |
| `dish_id` / `setmeal_id` | bigint | 菜品/套餐 id |
| `dish_flavor` | varchar(50) | 口味 |

### 3.4 `dining_session` 堂食会话

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `session_no` | varchar(32) | 会话号，分享/加入用，唯一 |
| `table_id` / `table_name` | bigint/varchar | 主桌 id 与桌号快照 |
| `order_id` | bigint | 关联堂食账单订单 |
| `owner_user_id` | bigint | 开台用户 |
| `guest_count` | int | 就餐人数 |
| `status` | int | 1 就餐中，2 待结账，3 已结账，4 已关闭（底层沿用原已取消状态，含取消/并桌迁移） |
| `aa_enabled` | tinyint | 是否 AA |
| `total_amount` | decimal(10,2) | 账单累计金额 |

### 3.5 `dining_table` 堂食桌台

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `name` | varchar(16) | 桌号，如 A01，唯一 |
| `seats` | int | 座位数 |
| `area` | varchar(16) | 大厅/包间 |
| `reservation_enabled` | tinyint | 是否允许预约 |
| `status` | int | 0 空闲，1 就餐中，2 待结账 |
| `qr_token` | varchar(64) | 扫码开台令牌，唯一 |

### 3.6 `dish` 菜品

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `name` | varchar(32) | 菜品名称，唯一 |
| `category_id` | bigint | 分类 id |
| `price` / `image` / `description` | decimal/varchar | 价格、图片、描述 |
| `status` | int | 0 停售，1 起售 |
| `stock` | int | 剩余库存，默认 100；下单扣减、取消回补 |

### 3.7 关系表

- `setmeal_dish(setmeal_id, dish_id, copies)`：套餐包含菜品及份数。
- `dish_flavor(dish_id, name, value)`：菜品口味，`value` 存 JSON/数组字符串。
- `dining_session_member(session_id, user_id, nickname, is_owner, paid_amount, pay_status)`：同桌成员与 AA 支付状态。
- `dining_session_table(session_id, table_id, is_primary)`：会话与桌台映射，支持并桌。
- `dining_payment(session_id, user_id, amount, pay_method, pay_status, pay_time)`：堂食支付/AA 记录。
- `dining_table_operation(session_id, from_table_id, to_table_id, operation_type, operator_id, operator_type)`：开台、转台、并桌、结账、关闭/取消流水。

## 4. 初始化与数据说明

1. 创建库（若不存在）：
   ```sql
   CREATE DATABASE IF NOT EXISTS orpl DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   ```
2. 建表：
   ```bash
   mysql -uroot -proot orpl < mysql/01-schema.sql
   ```
3. 导入演示数据（可选）：
   ```bash
   mysql -uroot -proot orpl < mysql/02-demo-data.sql
   ```
4. 旧库升级（已有 orders 表且存在派送中/已完成未支付数据时）：
   ```bash
   mysql -uroot -proot orpl < mysql/03-migrate-order-status.sql
   ```
5. 旧库升级（支持堂食同一订单多次加餐的轮次字段）：
   ```bash
   mysql -uroot -proot orpl < mysql/04-migrate-dining-round.sql
   ```
6. `02-demo-data.sql` 是迁移时生成的基线演示数据，不含后续联调产生的订单 91/92、地址 21、堂食会话 42 等运行期测试记录。当前开发库已包含这些记录，交付/重置环境时可按需重新导入。
7. 生产环境不要把数据库密码 `root/root`、Redis 密码 `root` 写死在配置里，建议改为环境变量或配置中心。

- 迁移动作：
  - `status=4` → `status=3`；

## 9. 2026-11-24 管理端关闭会话

本次新增管理端“关闭会话”操作，不新增/删除表、字段或索引：

- `dining_session.status=4`，管理端展示为“已关闭”；底层沿用原“已取消”状态值，并桌迁移的源会话也使用该值。
- 关闭时只将 `orders.status IN (1,2,3)` 的订单改为 `6已取消` 并回补库存；`5已完成`、`6已取消` 或 `payStatus=1已支付` 的订单保留，避免覆盖结账结果。
- `dining_table.status=0`，释放会话关联的全部桌台。
- 删除该会话的 `shopping_cart` 记录。
- `dining_session_member` 保留作为支付/AA 历史；会话关闭后不再通过 `/user/dining/session/mine` 返回。
- `dining_table_operation` 新增一条 `operation_type=5` 的关闭流水。
- 无 Redis 键变更；`mysql/01-schema.sql` 同步 `dining_session.status` 注释为“4已关闭（原已取消）”，无表结构、字段或索引变更，无新增迁移脚本。

## 10. 2026-11-24 堂食加餐合并与下单轮次

本次新增字段 `order_detail.dining_round`，用于区分堂食当前订单内的第几次下单：

- `dining_round int NOT NULL DEFAULT 1`，1 表示第一次下单，后续加餐递增为 2、3……；外卖订单固定为 1。
- 同一 `orders.dining_session_id` 首次提交创建订单，后续加餐复用当前进行中订单（`status IN (1,2,3)`），只追加 `order_detail` 并累加 `orders.amount` 与 `dining_session.total_amount`，不再生成新订单。
- 历史数据通过 `mysql/04-migrate-dining-round.sql` 添加字段并回填为 1；该脚本可重复执行。
- `mysql/01-schema.sql` 已同步 `order_detail.dining_round` 定义；`02-demo-data.sql` 的 120 条演示明细已在 `order_detail` 无列名 VALUES 中统一补写 `dining_round=1`，否则新增列后恢复演示库会因列数不匹配失败。
- 开发库已执行迁移，当前 151 条订单明细均为 `dining_round=1`（本轮联调新增数据已清理）。
- 无 Redis 键变更。
