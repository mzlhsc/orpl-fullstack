## 10. 删除假 API 层（2026-11-23 追加）

### 10.1 问题确认

迁移时保留了原 `orpl-pojo/api` 包，里面有四个“伪 Feign”接口：

- `DishClient`、`SetmealClient`、`UserClient`、`OrderClient`
- 方法上带 `@GetMapping` / `@PostMapping` 等 Spring MVC 注解，但没有 `@FeignClient`，也没有 HTTP 代理实现。

单体化后又补了 `LocalDishClient`、`LocalSetmealClient`、`LocalUserClient`、`LocalOrderClient`，调用链变成：

`业务 Service -> LocalXxxClient -> XxxInnerController -> Service/Mapper`

在同进程里绕了一圈 Controller，既没有真实服务边界，也没有 Feign 的序列化/负载均衡/独立部署意义。`api.dto.Category` 还是与 `ctgy/domain/po/Category` 重复的实体。

结论：保留这套 `api` 层只会增加重复 DTO、重复实体和假边界，应删除。

### 10.2 删除内容

| 类型 | 文件 | 数量 |
|---|---|---:|
| 伪 Feign 接口 | `orpl-pojo/.../api/client/DishClient.java`、`OrderClient.java`、`SetmealClient.java`、`UserClient.java` | 4 |
| 简单 DTO / 重复实体 | `AddressBookSimpleDTO`、`Category`、`DishSimpleDTO`、`SetmealDishItemDTO`、`SetmealSimpleDTO`、`UserSimpleDTO` | 6 |
| 本地适配器 | `orpl-service/.../service/local/LocalDishClient.java`、`LocalOrderClient.java`、`LocalSetmealClient.java`、`LocalUserClient.java` | 4 |
| 内部控制器 | `DishInnerController`、`DishStockInnerController`、`OrderInnerController`、`SetmealInnerController`、`UserInnerController` | 5 |

删除后 `orpl-pojo` 不再有 `com.mzlhsc.orpl.api` 包，`orpl-service` 不再有 `service/local` 和 `controller/inner` 包。

`orpl-service/src/main/resources/application.yml` 中 `mzlhsc.jwt.token-ttl`、`mzlhsc.auth.exclude-paths` 等自定义配置项在 IDEA 中被标黄，悬浮提示“无法解析配置属性”。

### 原因

- `JwtProperties`、`AuthProperties`、`WeChatProperties` 位于 `orpl-common` 模块，而 `application.yml` 位于 `orpl-service` 模块。
- 工程原先未引入 `spring-boot-configuration-processor`，编译期不生成 `META-INF/spring-configuration-metadata.json`；IDEA 只能看到当前模块自身的属性类（如 `AliyunOSSProperties`），解析不到 `orpl-common` 中的属性键。
- 运行期绑定本身正常：用 `Binder` 实测 `mzlhsc.jwt.token-ttl=12h` 可正常绑定到 `tokenTTL` 字段（`PT12H`），该提示只影响 IDE 补全，不影响启动。

### 改动

| 文件 | 改动 |
|---|---|
| `pom.xml` | 新增 optional 依赖 `spring-boot-configuration-processor`；`maven-compiler-plugin` 的 `annotationProcessorPaths`（`default-compile`、`default-testCompile`）补上该处理器，否则显式处理器路径会屏蔽它 |
| `orpl-common/src/main/resources/META-INF/additional-spring-configuration-metadata.json` | 新增。补充 `mzlhsc.jwt.token-ttl`、`mzlhsc.redisson.enabled` 两个属性：前者由处理器从字段 `tokenTTL` 生成的名字是 `mzlhsc.jwt.token-t-t-l`，需手工纠正为 `token-ttl`；后者来自 `@ConditionalOnProperty`，处理器不生成 |

| `orpl-service/target/classes/META-INF/spring-configuration-metadata.json` | 已生成，含 `mzlhsc.aliyun.*` |
| `additional-spring-configuration-metadata.json` 打包 | 已随 `orpl-common` 输出到 `target/classes/META-INF` |
